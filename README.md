# Git Guide 🌱

> Git을 처음 접하는 사람을 위한 **인터랙티브 도식 기반 Git 학습 가이드**
>
> v0.1.1 기준 · [변경 내역](release-notes/)

Git을 직접 다루지 않고도, Git 안에서 **무슨 일이 일어나는지 눈으로 보면서** 개념과 정확한 용어를 익히는 것을 목표로 합니다.
각 단계는 브라우저에서 바로 열 수 있는 HTML 페이지로 제공되며, 장면을 넘길 때마다
커밋·브랜치·HEAD 등의 변화가 도식(다이어그램)으로 표현됩니다.

---

## ✨ 특징

- **시각화 중심** — 로컬과 리모트 저장소, 워킹 트리(working tree) · 커밋 준비 영역 (Staging Area) · Git 디렉토리, 커밋 히스토리를 하나의 도식 틀로 보여줍니다.
- **인터랙티브** — 장면을 넘기며 도식이 어떻게 바뀌는지 보고, 도식의 요소를 누르면 그 용어의 뜻을 볼 수 있습니다.
- **커리큘럼 단계별 구성** — 기초 개념부터 협업까지 순서대로 따라가며 학습합니다.
- **설치 불필요** — 별도 빌드나 서버 없이 HTML 파일을 브라우저로 열기만 하면 됩니다.
- **정확한 용어** — 용어는 Pro Git 한국어판 표기를 따릅니다. 원고가 영문으로 쓴 용어는 "병합 (Merge)"처럼 한글 표현과 공식 용어를 함께 적어, 맥락을 잡으면서 공식 용어도 익힐 수 있게 합니다. 비유는 이해를 돕는 데만 씁니다.

## 📚 커리큘럼 (계획)

> 용어는 처음 보는 분도 맥락을 잡을 수 있게 **한글 표현 (공식 용어)** 형태로 함께 적었습니다. 레슨은 아직 만드는 중입니다.

| 단계 | 주제 | 다루는 내용 |
|:---:|---|---|
| 0 | 버전 관리란? | 로컬 버전 관리 → 중앙집중식 버전 관리(CVCS) → 분산 버전 관리 시스템(DVCS)으로서의 Git, Git과 GitHub의 차이 |
| 1 | 저장소 만들기 | 저장소를 새로 만들기, 저장소 복제 (Clone) — 히스토리 전체를 로컬로 복제하는 데까지, Git 디렉토리의 역할 |
| 2 | 세 가지 영역 | 워킹 트리 · 커밋 준비 영역 (Staging Area) · Git 디렉토리, 커밋 준비 영역에 올리기 (Stage), 파일 상태 수정됨 (Modified) · 커밋 준비됨 (Staged) · 커밋됨 (Committed) |
| 3 | 커밋 | 커밋하기 (Commit), 커밋 = 스냅샷, 커밋 히스토리 |
| 4 | 변경 확인과 되돌리기 | 변경 내용 확인(커밋 준비 전·후), 준비 취소 (Unstage), 수정됨 (Modified) 파일 되돌리기, 완료한 커밋 수정 |
| 5 | 브랜치 | 브랜치와 지금 위치 표시 (HEAD), 브랜치 만들기, 브랜치 이동 (Checkout) |
| 6 | 병합 (Merge) | 병합 (Merge), 빨리 감기 (Fast-forward)와 3방향 병합 (3-way Merge), 충돌 |
| 7 | 커밋 다시 쌓기 (Rebase) | 커밋 다시 쌓기 (Rebase), 병합 (Merge)과의 차이, 주의할 점(이미 공유한 커밋) |
| 8 | 리모트 저장소 | 리모트 저장소 등록과 `origin`, 리모트 브랜치·리모트 트래킹 브랜치, 올려 보내기 (Push), 가져오기 (Fetch), 가져와 합치기 (Pull) |
| 9 | 협업 흐름 | 내 계정으로 저장소 복사 (Fork), 병합 요청 (Pull Request)과 코드 리뷰, 브랜치 워크플로, GitHub 플로우 |
| 10 | 유용한 도구 | 하던 작업 임시 저장 (Stash), 태그, 파일 무시하기, 다른 브랜치의 커밋 가져오기 (Cherry-Pick) |

## 🚀 사용 방법

1. [GitHub 저장소 페이지](https://github.com/amurtare/git-guide)에서 **Code → Download ZIP**으로 내려받아 압축을 풉니다.
2. `index.html`을 브라우저로 엽니다.
3. 0단계부터 순서대로 장면을 넘기며 도식의 변화를 따라갑니다.

## 🏷️ 버전과 릴리즈

[Semver](https://semver.org)(`MAJOR.MINOR.PATCH`)를 따르며, 버전은 `VERSION` 파일 하나로 관리합니다.

| 구분 | 언제 올리나 |
|---|---|
| MAJOR | 커리큘럼 단계 재편, 레슨 경로 변경처럼 기존 링크가 깨질 때 |
| MINOR | 새 레슨이나 새 인터랙티브 도식이 추가될 때 |
| PATCH | 오탈자, 설명 수정, 도식 버그 수정 |

- 커리큘럼 0~10단계가 모두 완성되면 `1.0.0`이 됩니다.
- 버전별 변경 내역은 [`release-notes/`](release-notes/)에서 볼 수 있습니다.
- 릴리즈 절차는 [`docs/RELEASE_MANAGEMENT.md`](docs/RELEASE_MANAGEMENT.md)와 [`docs/UPDATE_CHECKLIST.md`](docs/UPDATE_CHECKLIST.md)를 따릅니다.

## 🤝 기여하기

오타 수정, 설명 개선, 새로운 단계 제안 모두 환영합니다.

1. **내 계정으로 저장소 복사 (Fork)** — 이 저장소를 내 계정으로 복사합니다.
2. 복사한 저장소에 작업할 새 브랜치를 만듭니다.
3. 변경 사항을 커밋합니다.
4. **올려 보내기 (Push)** — 그 브랜치를 리모트 저장소에 올립니다.
5. **병합 요청 (Pull Request)** — 원래 저장소에 내 브랜치를 병합해 달라고 요청합니다.

용어와 표기는 [`dev/design/glossary.md`](dev/design/glossary.md)를 따릅니다.
