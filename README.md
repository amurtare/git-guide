# Git Guide 🌱

> Git을 처음 접하는 사람을 위한 **인터랙티브 도식 기반 Git 학습 가이드**
>
> v0.1.1 기준 · [변경 내역](release-notes/)

Git을 직접 다루지 않고도, Git 안에서 **무슨 일이 일어나는지 눈으로 보면서** 개념과 정확한 용어를 익히는 것을 목표로 합니다.
각 단계는 브라우저에서 바로 열 수 있는 HTML 페이지로 제공되며, 장면을 넘길 때마다
커밋·브랜치·HEAD 등의 변화가 도식(다이어그램)으로 표현됩니다.

---

## ✨ 특징

- **시각화 중심** — 로컬과 리모트 저장소, 워킹 트리(Working Tree) · Staging Area · Git 디렉토리, 커밋 히스토리를 하나의 도식 틀로 보여줍니다.
- **인터랙티브** — 장면을 넘기며 도식이 어떻게 바뀌는지 보고, 도식의 요소를 누르면 그 용어의 뜻을 볼 수 있습니다.
- **커리큘럼 단계별 구성** — 기초 개념부터 협업까지 순서대로 따라가며 학습합니다.
- **설치 불필요** — 별도 빌드나 서버 없이 HTML 파일을 브라우저로 열기만 하면 됩니다.
- **정확한 용어** — 용어는 Pro Git 한국어판 표기를 따르고 영문 원어를 함께 보여줍니다. 비유는 이해를 돕는 데만 씁니다.

## 🚀 사용 방법

1. [GitHub 저장소 페이지](https://github.com/amurtare/git-guide)에서 **Code → Download ZIP**으로 내려받아 압축을 풉니다.
2. `index.html`을 브라우저로 엽니다.
3. 0단계부터 순서대로 장면을 넘기며 도식의 변화를 따라갑니다.

## 🏷️ 버전과 릴리즈

[Semver](https://semver.org)(`MAJOR.MINOR.PATCH`)를 따르며, 버전은 `VERSION` 파일 하나로 관리합니다.

| 구분 | 언제 올리나 |
|---|---|
| MAJOR | 커리큘럼 단계 재편, 레슨 경로 변경처럼 기존 링크가 깨질 때 |
| MINOR | 새 레슨이나 새 인터랙티브 도식이 추가될 때 |
| PATCH | 오탈자, 설명 수정, 도식 버그 수정 |

- 커리큘럼 0~10단계가 모두 완성되면 `1.0.0`이 됩니다.
- 버전별 변경 내역은 [`release-notes/`](release-notes/)에서 볼 수 있습니다.
- 릴리즈 절차는 [`docs/RELEASE_MANAGEMENT.md`](docs/RELEASE_MANAGEMENT.md)와 [`docs/UPDATE_CHECKLIST.md`](docs/UPDATE_CHECKLIST.md)를 따릅니다.

## 🤝 기여하기

오타 수정, 설명 개선, 새로운 단계 제안 모두 환영합니다.

1. 이 저장소를 Fork 합니다.
2. Fork 한 저장소에 작업할 새 브랜치를 만듭니다.
3. 변경 사항을 커밋합니다.
4. 그 브랜치를 리모트 저장소에 Push 합니다.
5. Pull Request를 생성합니다.

용어와 표기는 [`docs/design/glossary.md`](docs/design/glossary.md)를 따릅니다.

> 이 과정 자체가 이 가이드의 8~9단계에서 배우는 내용입니다 😉
