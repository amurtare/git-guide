# 공용 도식 모델

모든 레슨이 쓰는 하나의 도식 틀이다 (R1). 레슨마다 새 화면을 만들지 않고, 이 틀에서 공간·영역을 켜고 끄며 라벨만 바꾼다.
용어는 모두 [glossary.md](glossary.md) 표기를 따른다 (R6). 학습자는 Git을 실행하지 않고 도식을 보며 개념을 배운다 (R5).

> 확정: 2026-10-14 사용자 승인 (D1~D8, [dev/plan/checklist.md](../plan/checklist.md) "완료된 설계 · 공용 도식 모델")
> 2026-10-24: 3절·4절에 이름과 자리만 정한 요소·전이를 더했다. 구현 계약(파일 구조·설정 형식)은 [diagram-component-design.md](diagram-component-design.md).

## 1. 공간 (D3)

도식 속 **그림**의 단위다. 실제 서버·네트워크·여러 사용자는 없다 (정적 HTML, R4).

| 공간 | 개수 | 라벨 | 언제 나오나 |
|---|---|---|---|
| 로컬 | 1개 이상 | "나", "동료" (장면 설명용 이름) | 기본은 "나" 1개. CVCS의 한계, DVCS의 복제, 협업 장면에서만 "동료"를 더한다 |
| 서버 | 최대 1개 | 장면 종류에 따라 바뀜 (아래) | 로컬 VCS 장면에는 없다 |

서버 상자의 라벨은 장면 종류에 따라 용어집 표기로 바뀐다. 틀은 같고 이름만 바뀐다.

| 장면 종류 | 서버 상자 라벨 |
|---|---|
| 로컬 VCS | (서버 없음) |
| CVCS | 중앙 서버 |
| DVCS·Git | 리모트 저장소 |

## 2. 영역 (D2)

공간 안의 칸이다. 장면 종류에 따라 로컬 공간이 펼쳐진다.

| 장면 종류 | 로컬 공간의 영역 | 서버 공간의 영역 |
|---|---|---|
| 로컬 VCS | 파일 \| 로컬 데이터베이스 | — |
| CVCS | 파일 (버전 정보 없음) | 중앙 데이터베이스 |
| DVCS·Git | 워킹 트리 \| Staging Area \| Git 디렉토리 | 저장소 (커밋 히스토리) |

- **파일 영역 / 워킹 트리**: 파일 카드를 보여 준다.
- **로컬 데이터베이스 / 중앙 데이터베이스**: 버전 목록(파일의 변경 정보가 쌓인 목록)을 보여 준다.
- **Staging Area**: 다음 커밋에 들어갈 파일 카드를 보여 준다.
- **Git 디렉토리 / 리모트 저장소**: 커밋 히스토리를 보여 준다.
- CVCS 장면의 로컬에 버전 정보가 없다는 점이 DVCS와의 차이를 보여 주는 핵심이다. DVCS 장면에서는 로컬에도 저장소 전체가 있다.

## 3. 요소

> 모양(원·이름표·점선 등)은 이 문서의 기본안이다. 실제 시안은 Phase 1에서 화면으로 만들어 사용자 확인을 받는다. "색만으로 상태를 구분하지 않는다"는 접근성 원칙은 고정이다.

| 요소 | 모양 | 상태 표현 |
|---|---|---|
| 파일 카드 | 파일 이름이 적힌 카드 | Modified / Staged / Committed를 색과 표식(글자)으로 함께 구분한다. 색만으로 구분하지 않는다 |
| 커밋 노드 | 원. 짧은 식별 글자를 붙인다 | 스냅샷 하나. 화살표는 부모 커밋 방향을 가리킨다 |
| 브랜치 라벨 | 커밋 노드에 붙는 이름표 | 예: `main`. 새 커밋이 생기면 따라 움직인다 |
| HEAD | 브랜치 라벨을 가리키는 표식 | 지금 작업하는 로컬 브랜치를 가리킨다 |
| 리모트 트래킹 브랜치 | 로컬 Git 디렉토리 안의 이름표 (점선) | 예: `origin/main`. 리모트 저장소에 마지막으로 연결한 순간의 위치. 직접 옮길 수 없고 리모트 저장소와 연결할 때만 갱신된다는 것을 점선으로 표현한다 |

**이름과 자리만 정한 요소** (2026-10-24, [diagram-component-design.md](diagram-component-design.md) 결정 5·5-b·5-c). 뜻·모양·장면에서의 쓰임은 "정하는 곳"의 레슨 설계가 정한다.

| 요소 | 자리 | 정하는 곳 |
|---|---|---|
| 충돌 | 워킹 트리의 파일 카드에 붙는다. 히스토리 쪽 "병합 중단" 표시는 두지 않는다 | L6 |
| 태그 | 커밋 노드에 붙는다. 로컬 Git 디렉토리와 리모트 저장소 양쪽 히스토리에 놓일 수 있다 | L10 |
| 보관한 작업 목록 — 관련 용어: Stash | 로컬 Git 디렉토리 영역 안의 별도 목록 | L10 |
| 무시한 파일 — 관련 용어: 파일 무시하기 | 워킹 트리의 파일 카드에 붙는다 | L10 |
| 병합 요청 (Pull Request) | 리모트 저장소 영역 안의 요청 목록. 요청 하나는 보내는 브랜치와 받는 브랜치를 가리킨다 | L9 |
| 내 계정으로 저장소 복사 (Fork)의 복사본 저장소 | 정하지 않음 — 서버 상자 개수(1절)와 함께 [A6](../plan/open-questions.md#a6-fork-장면의-서버-쪽-저장소-개수) | L9 |

"보관한 작업 목록"·"무시한 파일"은 설계용 임시 이름이고 화면 용어가 아니다. 화면 라벨은 해당 레슨 설계에서 용어집 절차로 정한다(용어집에 없으면 먼저 추가).
이 밖의 요소가 필요하면 그 레슨 설계에서 사용자와 의논해 이 절에 먼저 더한다([diagram-component-design.md](diagram-component-design.md) 확장 규칙).

## 4. 전이

장면을 넘길 때 재생되는 움직임이다. 라벨은 용어집의 작업 이름이며, 학습자가 실행하는 명령이 아니다 (R5·D8).
도식 라벨은 R8 형식으로 **항상** "한글 표현 (원고 표기)"를 함께 적는다(예: 커밋 준비 영역에 올리기 (Stage)). 한글 표현은 [glossary.md](glossary.md) "한글 표현" 칸을 따른다.

| 전이 | 시작 → 도착 | 바뀌는 요소 |
|---|---|---|
| Stage | 워킹 트리 → Staging Area | 파일 카드가 Modified → Staged |
| Commit | Staging Area → Git 디렉토리 | 새 커밋 노드 생성, 파일 카드 Staged → Committed, 현재 브랜치 라벨이 새 커밋으로 이동 |
| Checkout | Git 디렉토리 → 워킹 트리 | HEAD가 다른 브랜치를 가리키고, 워킹 트리의 파일 카드가 그 버전으로 바뀐다. CVCS 장면에서는 중앙 서버 → 로컬 파일 영역 |
| Clone | 리모트 저장소 → 새 로컬 공간 전체 | 로컬에 저장소(커밋 히스토리 전체)가 복제되고, 리모트 트래킹 브랜치가 생기고, 워킹 트리가 채워진다. **1~7단계 장면에서는 리모트 트래킹 브랜치를 숨기고 8단계부터 표시한다**(2026-10-19 사용자 확정, [curriculum-scope-design.md](curriculum-scope-design.md)). 8단계에서 처음 보일 때의 설명 문장은 L8 설계에서 정한다 |
| Push | 로컬 Git 디렉토리 → 리모트 저장소 | 리모트에 없는 커밋이 리모트로 복사되고, 리모트 브랜치와 리모트 트래킹 브랜치가 앞으로 이동 |
| Fetch | 리모트 저장소 → 로컬 Git 디렉토리 | 로컬에 없는 커밋이 복사되고, 리모트 트래킹 브랜치만 이동. 로컬 브랜치·워킹 트리는 그대로 |
| Merge | 로컬 Git 디렉토리 안 | 두 브랜치의 작업이 합쳐진다. 결과 모양 두 가지 — 빨리 감기 (Fast-forward)와 3방향 병합 (3-way Merge, Merge 커밋 생성) — 의 장면 구성은 L6 설계에서 정한다 |
| Pull | 리모트 저장소 → 로컬 | Fetch 전이 다음에 Merge 전이를 이어서 재생한다 (Pull = Fetch + Merge) |

**이름만 정한 전이** (2026-10-24, [diagram-component-design.md](diagram-component-design.md) 결정 9). 범위에 나오고 용어집에 있는 전이다. 시작 → 도착과 바뀌는 요소는 "정하는 곳"의 레슨 설계에서 위 표로 옮겨 채운다.

| 전이 | 정하는 곳 |
|---|---|
| Unstage | L4 |
| Fast-forward · 3-way Merge | L6 (Merge와의 값 구분, Pull 마지막 단계 표시 포함) |
| Rebase | L7 |
| Fork | L9 (A6와 함께) |
| Pull Request | L9 (3절 요청 목록과의 관계 포함) |
| Stash · Cherry-Pick | L10 |

용어집에 이름이 없는 동작(L4의 Modified 파일 되돌리기·완료한 커밋 수정, L9의 Pull Request 병합)은 그 레슨 설계에서 용어집 → 이 절 → 구현 계약 순서로 더한다.

## 5. 표시 상태

모든 공간과 영역은 다음 셋 중 하나다.

| 상태 | 의미 |
|---|---|
| 숨김 | 그리지 않는다 |
| 흐리게 | 자리만 보여 준다. 아직 배우지 않았거나 이 장면의 초점이 아닌 곳 |
| 활성 | 이 장면의 초점 |

## 6. 레슨별 노출 범위

단계별 범위는 [curriculum-scope-design.md](curriculum-scope-design.md)(2026-10-19 확정)를 따르며, 아래 표는 그 범위로 다시 확인했다(변경 없음). 단계 안의 장면별 노출은 각 레슨 설계에서 정한다.
1~7단계에서는 리모트 트래킹 브랜치를 숨긴다(4절 Clone 행). 9단계 Fork 장면의 서버 쪽 저장소 개수는 [open-questions A6](../plan/open-questions.md#a6-fork-장면의-서버-쪽-저장소-개수)에서 정한다.
0단계 안의 장면 구성은 L0 설계 문서(미작성, A2)에서 정한다. 여기서는 0단계에서 로컬 VCS → CVCS → DVCS 순서로 공간과 영역이 나타난다는 틀만 정한다.

| 단계 | 로컬 | 서버 | 로컬 영역 |
|---|---|---|---|
| 0 | 나 (+동료) | 장면 종류에 따라 없음 → 중앙 서버 → 리모트 저장소 | 로컬 VCS·CVCS·DVCS 구성이 차례로 |
| 1 | 나 | 흐리게 (Clone 장면에서 활성) | DVCS·Git 구성, 영역 구분은 흐리게 |
| 2~4 | 나 | 흐리게 | 워킹 트리·Staging Area·Git 디렉토리 활성 |
| 5~7 | 나 | 흐리게 | Git 디렉토리(커밋 히스토리) 중심 |
| 8 | 나 | 활성 | 전체 |
| 9 | 나 + 동료 | 활성 | 전체 |
| 10 | 나 | L10 설계에서 정함 | L10 설계에서 정함 |

## 7. 조작 (D1)

- 장면 단위로 **이전 / 다음**으로 이동한다. 전이는 장면을 넘길 때 재생된다.
- **처음으로**: 레슨의 첫 장면 상태로 되돌린다.
- 도식의 공간·영역·요소를 누르면 그 용어의 용어집 정의가 뜬다.
  (2026-10-27 보충: 정의는 툴팁으로 뜬다. 도식 요소에 붙는 짧은 설명 툴팁(`notes`)을 띄우는 방식과 이 조작과의 관계는 구현 Phase 1 시안에서 정한다 — [diagram-component-design.md](diagram-component-design.md) 결정 14·15)
- 명령 입력, 드래그, 학습자가 상태를 직접 바꾸는 조작은 없다.

## 8. 배치 (D4)

- **데스크톱**: 로컬 왼쪽, 서버 오른쪽. 로컬이 둘이면 나(왼쪽) · 서버(가운데) · 동료(오른쪽).
- **모바일 폭(약 375px)**: 위아래로 쌓는다. 순서는 나 → 서버 → 동료. 가로 스크롤이 생기지 않아야 한다.
- 로컬 공간 안의 영역은 데스크톱에서 왼쪽→오른쪽(워킹 트리 → Staging Area → Git 디렉토리), 모바일에서 위→아래로 놓아 Stage → Commit 흐름이 한 방향으로 읽히게 한다.
- 라이트/다크 모드 모두에서 공간·영역의 경계와 파일 상태 구분이 보여야 한다.
