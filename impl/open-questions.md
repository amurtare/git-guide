# git-guide 미검증·미결 목록

## 운영 규칙

- **무엇을 넣나**: ① 실제 브라우저로 못 본 동작, Pro Git 원고로 확인하지 못한 설명·용어 ② 검수의 빈틈 ③ 외부 환경 의존 가정(브라우저 정책, GitHub 등) ④ 부작용 때문에 미룬 실행 ⑤ 미이행·미결정
- **언제**: 각 구현 단계를 마칠 때(커밋 전) — 새 항목 추가 + 해소된 항목 정리
- **해소되면**: 항목을 지우고 결과를 `project-memory/gotchas.md`(사실) 또는 `project-memory/decisions/`(정책)로 옮긴다. `progress.md`에는 ID만 적는다
- **ID**: 구획 문자 + 번호(`A1`). 지운 ID는 재사용하지 않는다
- 이 프로젝트의 미해결 이슈 장부는 이 파일 하나다 (`project-memory/open-questions.md`는 여기로 안내만 한다)

## A. 설계 미결 — 사용자와 정해야 하는 것

### A2 0단계 장면 구성
- **모르는 것**: R2의 구체 장면. 제안(2026-10-13, 용어는 2026-10-14 용어집 기준으로 고침): 0-1 파일을 복사해 버전을 관리하던 방식 → 0-2 로컬 버전 관리 → 0-3 중앙집중식 버전 관리(CVCS) → 0-4 분산 버전 관리 시스템(DVCS)으로서의 Git(공용 틀 완성) → 0-5 1~10단계 지도. 공간·영역 구성은 `docs/design/diagram-model.md`를 따른다
- **모르는 채 동작**: 구현하지 않는다
- **확인 방법**: 사용자와 의논 → `docs/design/lesson-00.md`. 사용자가 공유하려던 Perforce 자료(`perforce-ax-template`)가 서버 방식 장면의 참고가 될 수 있음
- **언제**: Phase 0 · 0단계 흐름
- **출처**: 프로세스 도입(2026-10-13)

### A3 Clone 개념을 다루는 단계
- **모르는 것**: Clone은 리모트 저장소를 전제하는데 README에서는 1단계에 있다. 제안: 0단계에서 두 공간을 먼저 보여 주고 1단계에 유지(A안) / Clone을 8단계로 이동(B안)
- **모르는 채 동작**: README 1단계 표기를 그대로 둔다
- **확인 방법**: 사용자 결정. B안이면 README 커리큘럼 표 수정
- **언제**: Phase 0 · 0단계 흐름
- **출처**: 프로세스 도입(2026-10-13)

### A4 용어집 "처음 나오는 단계" 잠정값과 README의 용어 미정 항목
- **모르는 것**:
  - 용어집 "처음" 칸과 `diagram-model.md` 6절 노출 범위는 현재 README 표 기준 잠정값이다
  - README 커리큘럼 표에 용어집에 아직 없는 용어가 있다: Fork, Pull Request, Rebase, Fast-forward 같은 Merge 방식, 태그 등
  - 단계 이름 "병합"·"리베이스"는 원고 표기(Merge, Rebase)와 다르다. 2026-10-14에는 단계 이름을 바꾸지 않았다
- **모르는 채 동작**: 잠정값으로 둔다. 레슨 플랜 때 해당 용어를 원고로 확인해 용어집에 먼저 넣는다
- **확인 방법**: "커리큘럼 단계별 범위 확정" 항목에서 사용자와 의논
- **언제**: Phase 0 · 커리큘럼 단계별 범위 확정
- **출처**: Phase 0 용어집·공용 도식 모델(2026-10-14)

### A5 R7(전체 계획 → 단계별 완성)에 맞춘 백로그 구성
- **모르는 것**: R7 "전체 계획을 먼저 세운 뒤, 한 단계씩 세부 구현까지 끝내고 다음 단계로" 에서 "전체 계획"에 무엇이 들어가는지. 특히 0단계 장면 설계(`lesson-00.md`)를 전체 계획(Phase 0)에 둘지, 0단계 구현 단계 안에서 할지. 현재 백로그는 "0단계 흐름"을 Phase 0에 두고, 0단계 구현을 Phase 1(공용 틀+첫 장면)과 Phase 2(나머지)로 나눠 두었다
- **모르는 채 동작**: 2026-10-14 승인된 플랜에 있던 변경(용어집 항목 분리, "커리큘럼 단계별 범위 확정" 항목 추가) 외에는 백로그 구성을 바꾸지 않는다. 다음 착수 지점은 확인 후 정한다
- **확인 방법**: 사용자 결정 → `impl/checklist.md`, `impl/README.md` 진행 방식
- **언제**: 다음 단계 착수 전
- **출처**: 2026-10-14 사용자 지시(R7)

## B. 배포·운영

### B1 화면 버전 표시와 `VERSION` 동기화
- **모르는 것**: `file://`에서는 페이지가 `VERSION`을 읽을 수 없어, 푸터 버전을 HTML에 직접 적으면 사본이 2개가 된다
- **모르는 채 동작**: 릴리즈 체크리스트 1번에서 수동으로 같은지 확인
- **확인 방법**: (a) 수동 확인 유지 (b) `assets/js/version.js`를 버전 소스로 (c) 릴리즈 워크플로에서 두 값 비교
- **언제**: Phase 1 · `index.html`을 만들 때
- **출처**: v0.1.0(2026-10-13), `project-memory/open-questions.md`에서 이관

### B2 공개 방식 (GitHub Pages 여부)
- **모르는 것**: 웹 배포 여부. 내려받기 안내 방식은 `project-memory/decisions/update-delivery-download.md`. README는 내려받은 파일의 `index.html`을 여는 방법만 안내한다
- **모르는 채 동작**: 로컬 열람만 지원
- **확인 방법**: 사용자 결정 → 릴리즈 체크리스트 8번, README 사용 방법 갱신. README 사용 방법은 2026-10-14부터 "Download ZIP 후 `index.html` 열기"로 안내한다(D8) — B2 해소 때 다시 확인
- **언제**: 첫 레슨 완성 시(Phase 2)
- **출처**: v0.1.0(2026-10-13), `project-memory/open-questions.md`에서 이관

- **모르는 채 동작**: 수동 스모크(README "실행 환경" 절차)만 한다
- **확인 방법**: 사용자 결정 → 도입 시 `package.json`(개발 전용) 여부와 버전 소스(`VERSION`) 관계도 함께 정리
- **언제**: Phase 0 · 개발 도구 결정
