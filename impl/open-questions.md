# git-guide 미검증·미결 목록

## 운영 규칙

- **무엇을 넣나**: ① 실제 브라우저·실제 Git으로 못 본 동작 ② 검수의 빈틈 ③ 외부 환경 의존 가정(브라우저 정책, GitHub 등) ④ 부작용 때문에 미룬 실행 ⑤ 미이행·미결정
- **언제**: 각 구현 단계를 마칠 때(커밋 전) — 새 항목 추가 + 해소된 항목 정리
- **해소되면**: 항목을 지우고 결과를 `project-memory/gotchas.md`(사실) 또는 `project-memory/decisions/`(정책)로 옮긴다. `progress.md`에는 ID만 적는다
- **ID**: 구획 문자 + 번호(`A1`). 지운 ID는 재사용하지 않는다
- 이 프로젝트의 미해결 이슈 장부는 이 파일 하나다 (`project-memory/open-questions.md`는 여기로 안내만 한다)

## A. 설계 미결 — 사용자와 정해야 하는 것

### A1 공용 도식 상세안
- **모르는 것**: R1(로컬·리모트 공용 틀)의 구체 구성. 대화(2026-10-13)에서 나온 제안: 로컬 = 작업 디렉터리 · 스테이징 · 로컬 저장소(커밋 그래프), 리모트 = 원격 저장소(같은 모양의 커밋 그래프), 로컬 그래프에 `origin/main` 표시, 명령은 영역 사이 화살표 애니메이션, 레슨별로 영역을 켜고 끔
- **모르는 채 동작**: 구현하지 않는다. Phase 0 첫 항목 플랜에서 확정
- **확인 방법**: 사용자와 의논 → `docs/design/diagram-model.md`
- **언제**: Phase 0 · 공용 도식 모델
- **출처**: 프로세스 도입(2026-10-13)

### A2 0단계 장면 구성
- **모르는 것**: R2의 구체 장면. 제안: 0-1 파일 복사로 관리 → 0-2 로컬 버전 관리 → 0-3 서버(중앙) 버전 관리 → 0-4 분산 버전 관리(Git, 공용 틀 완성) → 0-5 1~10단계 지도
- **모르는 채 동작**: 구현하지 않는다
- **확인 방법**: 사용자와 의논 → `docs/design/lesson-00.md`. 사용자가 공유하려던 Perforce 자료(`perforce-ax-template`)가 서버 방식 장면의 참고가 될 수 있음
- **언제**: Phase 0 · 0단계 흐름
- **출처**: 프로세스 도입(2026-10-13)

### A3 `git clone`을 다루는 단계
- **모르는 것**: `clone`은 리모트를 전제하는데 README에서는 1단계에 있다. 제안: 0단계에서 두 공간을 먼저 보여 주고 1단계에 유지(A안) / `clone`을 8단계로 이동(B안)
- **모르는 채 동작**: README 1단계 표기를 그대로 둔다
- **확인 방법**: 사용자 결정. B안이면 README 커리큘럼 표 수정
- **언제**: Phase 0 · 0단계 흐름
- **출처**: 프로세스 도입(2026-10-13)

## B. 배포·운영

### B1 화면 버전 표시와 `VERSION` 동기화
- **모르는 것**: `file://`에서는 페이지가 `VERSION`을 읽을 수 없어, 푸터 버전을 HTML에 직접 적으면 사본이 2개가 된다
- **모르는 채 동작**: 릴리즈 체크리스트 1번에서 수동으로 같은지 확인
- **확인 방법**: (a) 수동 확인 유지 (b) `assets/js/version.js`를 버전 소스로 (c) 릴리즈 워크플로에서 두 값 비교
- **언제**: Phase 1 · `index.html`을 만들 때
- **출처**: v0.1.0(2026-10-13), `project-memory/open-questions.md`에서 이관

### B2 공개 방식 (GitHub Pages 여부)
- **모르는 것**: 웹 배포 여부. README는 "클론 후 `index.html` 열기"만 안내한다
- **모르는 채 동작**: 로컬 열람만 지원
- **확인 방법**: 사용자 결정 → 릴리즈 체크리스트 8번, README 사용 방법 갱신
- **언제**: 첫 레슨 완성 시(Phase 2)
- **출처**: v0.1.0(2026-10-13), `project-memory/open-questions.md`에서 이관

## C. 검수·도구

### C1 검수자 지정 모델
- **모르는 것**: 독립 검수자로 쓸 모델·에이전트. 현재 Codex/Copilot 플러그인 미설치라 플랜 종료 hook은 통과만 한다
- **모르는 채 동작**: 맥락을 물려받지 않는 새 서브에이전트로 검수하고, 실제 실행 모델을 로그에 남긴다
- **확인 방법**: 사용자 결정 → `impl/README.md` 확정 전제
- **언제**: Phase 0 · 개발 도구 결정
- **출처**: 프로세스 도입(2026-10-13)

### C2 자동 확인 도구
- **모르는 것**: 레슨 인터랙션을 자동으로 확인할 도구. 후보: Playwright(컨테이너에 Chromium 설치됨) 스크립트를 개발 전용으로 둠. "빌드 없음" 원칙(R4)은 배포물에 대한 것이라 개발 전용 도구와 충돌하지 않는다고 보지만 확인 필요
- **모르는 채 동작**: 수동 스모크(README "실행 환경" 절차)만 한다
- **확인 방법**: 사용자 결정 → 도입 시 `package.json`(개발 전용) 여부와 버전 소스(`VERSION`) 관계도 함께 정리
- **언제**: Phase 0 · 개발 도구 결정
- **출처**: 프로세스 도입(2026-10-13)
