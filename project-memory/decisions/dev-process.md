# 개발 프로세스: 장기 개발 프로세스(최신 가이드) 적용, 루트 `dev/`, 설계 완료 범위 A

**결정 (2026-10-14)**

1. 사용자가 준 최신 `LONG_TERM_DEV_PROCESS.md`(Plan → Design → Impl)를 적용한다. 이전 가이드(구현 루프만)를 대체한다.
2. plan · design · impl · evidence를 **루트 `dev/` 아래 한 폴더**에 둔다. 사이트 코드(`index.html`·`lessons/`·`assets/`)는 루트에 둔다.
3. 가이드 사본은 원문 그대로 두지 않고 이 저장소 구조에 맞춘 **적용본**(`dev/LONG_TERM_DEV_PROCESS.md`)으로 둔다. 바꾼 범위는 적용본 머리말에 적는다.
4. **설계 완료 범위 A** — 모든 단위의 설계를 끝낸 뒤 구현에 들어간다. 0단계 장면 설계는 Design 단계에서 한다. (옛 `impl/open-questions.md`의 A5 해소)

## 에이전트 판단 (위의 연장선인 진행 방식)

- 단위 = 커리큘럼 단계, ID `L0`~`L10`(안정 식별자, 재번호화 금지). 공용 도식 컴포넌트의 구현 계약은 별도 설계 항목 `U-diagram`.
- 문서 배치: Phase 0 설계 항목·승인된 명세 → `dev/plan/checklist.md`, 미결 장부 → `dev/plan/open-questions.md`(ID 유지), 구현 Phase 1~3은 초안으로 `dev/impl/checklist.md`에 보존.
- `project-memory/`는 루트에 둔다(hook이 이 경로를 쓰고, 가이드에서도 별도 공용 기록).
- **경계**: 진행 방식(문서 배치·ID·백로그 구성)은 에이전트가 정하고 기록한다. 설계 결정(커리큘럼 범위·장면·용어·아키텍처)은 계속 사용자 확인을 받는다(R3).

## 운영 원칙 추가

- 결정 문서의 본문은 바꾸지 않는다(뒤집히면 새 문서 + Superseded 표시). 단, 파일 이동에 따른 **링크 경로만 고치는 것은 내용 변경이 아니므로 허용**한다.
- `project-memory/log.md`는 append-only라 옛 경로를 그대로 둔다.
