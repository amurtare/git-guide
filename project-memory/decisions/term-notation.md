# 용어 표기: 한글 표현 (원고 표기) 병기 (R8)

**결정 (2026-10-19, 사용자 지시)**

> "전체적으로 지금과 같은 한글 표기 옆에 원고 표기를 다른 브랜치의 커밋 가져오기 (cherry-pick) 형태로 해줘. 처음 접하는 사람들이 대상이기 때문에 한글화 표현으로 맥락을 구성하고, 옆에 공식 용어를 표기해줌에 따라 공식 용어도 인지하게 하는 거야. 이거 지침으로도 해줘"

| 항목 | 내용 | 근거 |
|---|---|---|
| 형식 | **한글 표현 (원고 표기)** — 예: 다른 브랜치의 커밋 가져오기 (Cherry-Pick). 괄호 안은 원고 주 표기(D6). 사용자 예시의 소문자 "cherry-pick"은 원고 주 표기 "Cherry-Pick"으로 쓴다 | 위 원문 |
| 대상 | 원고 표기가 **영문**인 용어만(Staging Area, Stage, Commit, Merge, Push 등). 원고가 한글·음차로 적은 용어(워킹 트리, 브랜치, 커밋, 저장소, 태그 등)는 원고 표기 그대로 | 사용자 "모두 추천 안으로 해줘" (2026-10-19) |
| 빈도 | 단계 이름·목차·장면 제목·도식 라벨·용어 카드는 **항상** 병기. 본문 설명문은 **장면마다 처음 한 번** 병기하고 그 장면 안에서는 한글 표현만 | 같은 답 |
| 단계 이름 | 6단계 "병합 (Merge)", 7단계 "커밋 다시 쌓기 (Rebase)" — 2026-10-14의 "병합"·"리베이스"와, 같은 세션 앞선 답 "Merge/Rebase로 변경"을 대체 | 같은 답 |
| Checkout 예외 | 0단계만 CVCS 기준 "중앙 서버에서 받아 오기 (Checkout)", 1단계부터 Git 기준 "브랜치 이동 (Checkout)" | 사용자 "Checkout 은 0단계 만 예외로 CVCS 기준으로 표기하고, 그 이후부터는 Git 기준으로 해줘" |
| 한글 표현 값 | [dev/design/glossary.md](../../dev/design/glossary.md) "한글 표현 (R8)" 칸이 단일 소스 | 사용자 "나머지는 동의" (용어 후보표) |

**기존 규칙과의 관계**
- **폐기 가설과 다르다**: 2026-10-14에 폐기된 것은 쉬운 말로 용어를 **대체**("기록하기", "준비 영역")하는 안이었다(R6). R8은 **병기**다 — 공식 용어는 항상 화면에 남고, 한글 표현은 맥락을 돕는다.
- **D5는 그대로**: 괄호 안 공식 용어와 원고가 한글로 적은 용어에 "원고 표기 그대로"가 적용되고, 원고가 한글로 적은 용어의 처음 영문 병기(예: 워킹 트리(working tree))도 유지한다. R8은 영문 원고 용어의 화면 표기 형식만 정한다.
- **지침 등급**: "지침으로도 해줘"에 따라 CLAUDE.md ★ 절대 규칙에 R8로 올렸다(진행 방식 지시를 R7로 올린 선례와 같은 방식).
