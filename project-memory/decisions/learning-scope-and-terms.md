# 학습 범위·용어·진행 방식 (R5·R6·R7)

**결정 (2026-10-14, 사용자 지시)**

| # | 규칙 |
|---|---|
| R5 | 학습자는 Git을 직접 사용하지 않고 **개념만** 배운다. 명령 입력·실행 UI를 만들지 않는다 |
| R6 | 학습이 목적이므로 **용어는 정확하게** 다룬다. 기준은 Pro Git 한국어판이고, `docs/design/glossary.md` 하나를 따른다 |
| R7 | **전체 계획을 먼저 세운 뒤, 한 단계씩 세부 구현까지 끝내고 다음 단계로 간다** |

**계기**
- 공용 도식을 설계하면서 에이전트가 "명령 버튼·터미널 입력"을 선택지로 내놓았다. 사용자가 "사용자가 직접 Git을 쓰는 게 아니라 개념만 배운다"고 정정했다 → R5.
- 쉬운 말로 개념만 보여 주자는 제안("기록하기", "준비 영역")에 사용자가 "학습이 목적이니 용어는 정확해야 한다"고 정정했다 → R6.
- 진행 방식에 대한 지시 → R7.

**R5·R6의 세부 결정 (같은 날 사용자 결정·승인)**

| # | 내용 |
|---|---|
| D5 | 표기는 Pro Git 한국어판 원고 그대로. 맞춤법과 달라도 원고 우선("디렉토리"), 원고가 영문인 용어는 영문 유지("Staging Area"). 처음 나올 때 영문 병기 |
| D6 | 원고 안에 이표기가 있으면 주 표기 + 별칭. **워킹 트리**(주, 1.3절 세 영역 그림 이름) = 워킹 디렉토리(별칭, 2장 이후 다수). 둘 다 같은 것임을 학습자에게 알려 준다 |
| D7 | 기본 브랜치 이름은 **`main`**. `master`는 브랜치를 처음 소개할 때 "예전 기본 이름이자 Pro Git이 쓰는 이름"으로 한 번만 언급 |
| D8 | **용어만 쓴다.** Commit·Push 같은 작업 이름은 용어로 쓰지만 `git commit` 같은 명령어 형태는 사이트와 README 전체(사용 방법·기여하기 포함)에 쓰지 않는다. 학습자가 bash에서 명령을 칠 일이 없기 때문 |

**근거 원고**: <https://github.com/progit/progit2-ko> 커밋 `f50647da032bf210ef91802290d60d05da1a9416` (2025-03-05). 이 환경에서는 git-scm.com이 막혀 GitHub 원고를 근거로 삼았다.

**적용 범위 밖**: 메인테이너용 운영 문서(`.github/`, `.claude/`, `docs/RELEASE_MANAGEMENT.md`, `docs/UPDATE_CHECKLIST.md`, `impl/`의 절차 속 git 명령)는 학습자가 보는 곳이 아니라 D8 적용 대상이 아니다.
