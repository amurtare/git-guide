# 레슨 화면: 슬라이드형, 도식 중심, 텍스트는 나레이션과 툴팁으로

**결정 (2026-10-27, U-diagram 설계 세션)**: [visual-style.md](visual-style.md)의 "첫 파일럿(공통 폼)의 구성은 괜찮지만"과 "화면 구성은 diagram-model.md와 레슨 설계가 정한다"를 보충·일부 대체한다. 시각 언어(토큰·서체·배경)는 visual-style 그대로다.

**사용자 결정** (아래 원문이 근거)
- 레슨 화면은 상자(프레임)로 나누지 않고, 화면 전체를 쓰는 **슬라이드형**(PPT 같은 느낌)이다. (에이전트 해석, 사용자 확인 필요: "상자로 나누지 않는다"는 여러 상자로 쪼개지 않는다는 뜻으로 읽고, 아래 보충의 타이틀 영역 + 도식 카드 하나 구성과 함께 둔다)
- **도식이 화면에서 가장 큰 비중**을 차지한다. 텍스트는 최소로 둔다.
- 화면 설명은 **나레이션** 컨셉으로 보여 준다(설명하는 사람이 있는 느낌).
- 필요한 설명은 **툴팁**으로 준다. 툴팁은 용어 정의에 더해 도식 요소에 붙는 짧은 설명(설정 계약 `notes`)도 담는다.

**사용자 결정 보충 (2026-10-27, 슬라이드형 시안을 보고)**
- 나레이션은 화면을 나누는 띠가 아니라 **도식 위에 얹힌 레이어**(말풍선 카드)로 둔다 — 화면 전체를 도식이 쓰는 느낌. 시안에서는 끌어서 옮길 수 있다.
- 나레이션 표현 1~4 모두 채택 방향: ① 화자 아이콘에서 이어지는 말풍선 모양 ② 말하는 말투 ③ 본문이 타자 치듯 나타남 ④ 본문은 짧게, 나머지 설명은 도식 요소 설명 툴팁(`notes`)으로.
- 원문: "1~4 모두 괜찮은데, 프레임으로 영역을 나눈 것이 별로야. 프레임으로 나누지 말고, 레이어로 위에 얹혀진 형태는 어떨까? 그럼, 화면을 전체적으로 사용하는 느낌이잖아." (그림: 화면 전체 도식 위 아래쪽 가운데에 "Dragble 나레이션" 카드)
- 나레이션 레이어의 세부 배치, 끌어 옮기기·타자 효과를 실제 사이트에 넣을지, 말투 문장 자체는 Phase 1 시안 확인·레슨 설계에서 정한다(위 1~4와 레이어는 사용자가 고른 방향).

- 화면을 **타이틀 영역**(종이 배경 위 머리표·큰 제목·설명)과 **도식 영역**(큰 카드 하나)으로 크게 나눈다 — 디자인 컨셉 원본 페이지의 "제목 → 카드 안 차트" 구성처럼. 그라데이션은 쓰지 않는다. 원문: "아니야. 그라데이션 표현은 저런 식으로 하면 안될 것 같아서 일단, 위에 디자인 컨셉처럼 카드 형태로 프레임을 잡아줘", "타이틀과 도식 영역을 이런 식으로 크게 구분하는거지" (참고 그림: 원본 페이지의 제목·설명 아래 큰 카드에 담긴 차트)

- 상단(레슨 이름·안내 등 타이틀 영역)은 도식을 넓히려고 글씨를 줄이지 않는다. 원문: "상단 부분은 타이틀이니까 도식영역을 최대화 하기 위해 이 부분까지 폰트 크기를 줄일 필요는 없어"

**사용자 제안 — 시안에 적용, 확정 전** (사용자가 시안을 보고 정한다)
- 나레이션 말풍선은 화면과 **반대 시간 테마**로 둔다 — 낮 테마 화면에서는 밤 테마, 밤 테마 화면에서는 낮 테마. 원문(제안): "그리고 나레이션은 반대 시간 테마를 쓰는 것은 어때? 기본이 낮 테마라면, 나레이션은 밤테마"

**에이전트 판단** (사용자 위임 2026-10-24 "이번 세션은 특별하게 다룰 결정사항은 없어서 니가 권장하는 방향으로 모두 진행해줘 질문 안해도 돼" 아래)
- 나레이션은 장면의 `title`·`body`를 펼친 것이고, 텍스트 칸을 따로 더 두지 않는다. 파일럿의 고정 용어 카드 칸은 두지 않는다(용어 정의는 툴팁).
- 툴팁의 R8 표기는 라벨·용어 카드와 같이 "항상 병기"로 다룬다(나레이션 없이 따로 읽힐 수 있으므로).
- 구체 배치(나레이션·툴팁·장면 이동의 자리와 모양, 모바일 폭)와 `notes` 툴팁을 띄우는 방식·D1 조작과의 관계는 구현 Phase 1 시안에서 사용자 확인을 받는다.

**에이전트 판단 — 시안 구현 세부** (2026-10-27, 사용자가 시안을 보고 고칠 수 있는 값, Phase 1 시안 확인 대상)
- 카드 안의 두 공간은 색 면 없이 단색 구분선으로 나누고(그라데이션 거절의 결과로 고른 방법), 나레이션은 카드 위에 얹힌 레이어로 둔다.
- 도식 카드는 visual-style 토큰(surface 배경, 옅은 테두리, 그림자 e2, 큰 반경)으로 만든다. 공간 사이 구분선은 단색 1px. 장면 번호는 타이틀 영역 머리표 줄 오른쪽.
- 타자 효과는 움직임 줄이기 설정에서 끄고, 말풍선을 누르면 바로 완성된다. 화면 낭독기에는 제목과 본문을 한 번에 알린다.
- 나레이션 끌기는 넓은 화면에서만, 화면 밖으로 나가지 않게 제한하고, 손잡이를 두 번 누르거나 Home 키로 처음 자리로 돌아간다.

**사용자 원문**
- 처음 제안: "화면 형태에서 서술형의 텍스트 설명이 필요한 케이스는 공용으로 사용할 수 있는 나레이션 패널을 추가해서 표현하는건 어떨까? 누군가 설명하는 사람이 있는 느낌이지"
- 의도: "현재 너무 프레임으로 나누어져 있는데, 사용자에게 화면을 전체적으로 쓰고 있는 느낌을 주고 싶은거야. PPT 같은 느낌이지. 그래서 화면 설명을 나레이션 처럼 컨셉을 잡았던 것이고"
- "도식이 화면 비중이 가능 크고, 텍스트는 최소한으로 줄이고 싶은 거야. 필요하다면 필요한 부분에 툴팁 형태로 제공하고"
- 툴팁에 도식 요소 설명도 담을지: "(나)"

**기존 규칙과의 관계**
- D1(요소를 누르면 용어 정의)은 그대로다 — 보여 주는 방식이 고정 카드에서 툴팁으로 바뀐다. `notes` 툴팁을 띄우는 방식이 D1 조작 목록에 영향을 주는지는 Phase 1 시안에서 정한다(그 전까지 D1은 바뀌지 않는다).
- R1: 모든 레슨이 같은 슬라이드형 틀을 쓴다.
