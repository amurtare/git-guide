# 업데이트 전달: 내려받기로 안내하고, 앱 내 확인 기능은 만들지 않는다

**결정 (2026-10-14)**: [update-delivery.md](update-delivery.md)를 대체한다.

**바뀐 점**
- 이전 결정은 클론한 학습자가 새 버전을 받는 방법을 명령어로 안내하며 "그것 자체가 이 가이드에서 가르치는 내용"이라고 했다.
- R5(학습자는 Git을 직접 사용하지 않는다)·D8(README에도 명령어 형태를 쓰지 않는다)에 따라 README 사용 방법은 "Download ZIP 후 `index.html` 열기"로 바뀌었다.
- 이 바뀜이 이전 결정의 재검토 조건("오프라인 배포판(zip 등)을 따로 배포하게 되면")에 해당한다.

**결정 내용**
- 앱 내 업데이트 확인 기능은 여전히 만들지 않는다. 배포된 사이트를 보는 학습자는 항상 최신본을 보고, 내려받은 학습자는 새 버전을 다시 내려받는다.
- 무엇이 바뀌었는지는 `release-notes/`로 알린다. 페이지가 생기면 `index.html` 푸터에 현재 버전과 릴리즈 노트 링크를 둔다.
- 공개 방식(GitHub Pages 여부)과 내려받기 안내는 [dev/plan/open-questions.md B2](../../dev/plan/open-questions.md#b2-공개-방식-github-pages-여부)에서 함께 정한다.
