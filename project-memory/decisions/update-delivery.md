# 업데이트 전달: 앱 내 확인 기능을 만들지 않는다

**결정 (2026-10-13)**: 원본 가이드 6단계의 "앱 내 업데이트 배너"는 구현하지 않는다.

**이유**
- 웹으로 보는 학습자는 배포된 사이트(GitHub Pages 등)가 push 즉시 갱신되므로 항상 최신본을 본다. 확인할 대상이 없다.
- 클론해서 보는 학습자는 `git pull`로 갱신하며, 이것 자체가 이 가이드에서 가르치는 내용이다.
- 원격 API 호출을 넣으면 오프라인·`file://` 환경에서 동작이 불안정해지고, 입문자 대상 정적 사이트에 비해 복잡도가 크다.

**대신 하는 것**
- `index.html` 푸터에 현재 버전과 `release-notes/` 링크 표시 (페이지가 생기면)
- 릴리즈마다 Git 태그, 필요하면 GitHub Release 작성

**재검토 조건**: 오프라인 배포판(zip 등)을 따로 배포하게 되면 다시 판단한다.
